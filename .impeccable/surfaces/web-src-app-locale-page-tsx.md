# MoneyWorks home: direction contract

## SCOPE

One static-first personal-finance hub per locale. Visitor mode: Operate/Read. Country-neutral, English default, Swedish available. This is a basic site layout with native navigation and clearly planned tools, not a functioning dashboard or calculator.

## THESIS

Give the visitor a useful place to start without pretending to know their finances. Clear destinations and expandable tool plans carry the page; the original woven M/W mark gives it its own identity.

## OWN-WORLD

Owner-selected C, Bright works: charcoal #181c18, lime #d6fb79, ivory #f8f8f0, bold uppercase Manrope and sharply cornered contrasting tool panels. A large tilted original M/W mark carries two useful anchor labels. A localized light counterpart is available through a small enhancement. No fake charts, account figures, currency signs or commercial proof.

## STORY

Brand and top navigation; an introduction answered by two real starting questions; two explicitly planned tools; useful expandable information; a short statement of purpose; a quiet footer with real infrastructure status.

## FIRST VIEWPORT

At 1440px, use a centred 1160px frame. The logo, useful navigation, introduction and both tool choices are visible. The native planned-tool disclosures are the signature interaction, with plus-to-close feedback and readable content rather than an interrupting modal.

## FORM

The initial unapproved draft used Taste's pastel-consumer sheet, seed 1511364593, and Impeccable reference seed:a6bbc7ed3b12c5cd (grounded candidate 4). That colour treatment is superseded by the owner's explicit C selection. The rejected icon/sidebar shell remains inappropriate for the single-page top-navigation requirement. The larger introductory heading belongs to a public tool hub, not an account dashboard. A shadow is used only for floating mobile navigation.

No raster imagery or financial demonstration data is needed for this tool-index surface. This is an owner-selected visual starter, not approval for additional tools, blog publishing or video features. Visual checks and application behaviour are verified separately; the mockup board remains a distinct review surface.
